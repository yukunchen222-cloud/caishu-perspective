## 隔离规则

运行某一个 `group_id` 时，应从模型可见输入中同时排除：

1. 该组的完整文章、`catalog.json` 对应条目、分析卡、主题索引或缓存摘录；
2. 该文章的同源版本、交叉发布摘要、简书映射/目录卡及可由标题反查出的版本；
3. 从该文章整理出的衍生案例、原则、方法或测试提示；
4. `as_of` 之后的文档和未来版本。

因此开发案例与原则只使用 2025 年及以前资料；不能用 2026 年这 8 篇文章先提炼再拿来做开发材料。题组隔离是按组而不是只按单题进行，原题与两个变体必须一起隐藏全文及其衍生内容。边界题的 `held_out_source_ids` 为空；其 `as_of` 是评测时间截点，不是可据此引用的来源日期。

## 导出后再试用

不要把整个仓库交给评分对象。使用只复制允许文件的导出器：

```bash
python scripts/prepare_eval.py --source-root . --suite evals/decisions.json --case-id g02-author --output ../caishu-eval-g02 --variant optimized
```

输出必须是不存在的新目录，不能在源 Skill 内；未知排除ID、越界路径或已存在输出会报错，不覆盖旧结果。包内 `runtime/` 只含过滤后的运行入口、脚本、目录、允许原文/分析和依赖仍可见的案例/原则；`request.json` 只有问题和日期。`receipt.json` 供维护者验收，包含文件哈希和过滤情况；它不是答题输入。

让独立试用者只读 `runtime/` 和 `request.json`，不得读原库、评分gold、receipt、网络或其他试用答案；用另一个输出文件保存真实回答，再由维护者按gold和原文审阅。旧版方法如含被留出来源，导出时删除整个依赖段落，并在receipt标明净化，不能宣称逐字不变的基线。`receipt.json` 最后写入，缺少回执的目录不是完成包。

这是允许文件清单和工具指令级隔离，不是操作系统沙箱；它不能消除预训练记忆、未识别语义近重复或评分者偏差。更严格评测需独立权限环境和外部评分。可为同批题使用更早的共同资料截点，但必须对基线/优化版相同，并记录与原逐题as_of的区别。

## 评分与报告边界

- 目录标题、简书作者页短导语、文件存在、分析卡或模型记忆都不能替代正文证据，也不能支持逐字引用。
- `counterfactual` 的 `gold.author_direction` 明确以“本次应用判据（非作者原话）”开头；变体改变一个影响选择的条件，不能把变体答案倒写成作者说过。
- `evidence_boundary` 题在资料不足时保持 `source_refs: []`，不为了形式凑引用；身份、动机、当前事实、未来预测和效果问题要分别标记未知或待核验。
- 本库未提供实际效果、样本、对照或读者长期结果，也没有防止模型调用预训练记忆的机制。所有题的 `outcome_status` 为 `not-observed`，不能据此声称方法有效、读者改善或成功率。
- 后续评测只统计实际运行并记录的题；未运行、跳过或只通过静态校验的题不计入结果。
