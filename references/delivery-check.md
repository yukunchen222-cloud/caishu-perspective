# 复杂决策的交付检查

试用中模型曾给了本地路径却漏原文URL，也曾建议正确但下一步没有期限/投入界限。因此把结构化草稿交给可运行检查器，再写自然回答；这是格式和来源门，不是“决策正确性评分”。短问答、纯证据边界解释不需要机械使用本表。

## 输入

向 `python scripts/check_decision.py` 的标准输入传入一个JSON对象；也可用 `--input <已保存草稿路径>`，不要仅为检查而把用户隐私写进未知目录。不需要第三方库、联网或安装。PowerShell可通过管道传入UTF-8 JSON，宿主也可直接写进进程stdin。脚本不会保存草稿。

```json
{
  "evidence_status": "source-backed",
  "author_view": "已读原文在条件X下支持Y；不能确认的作者立场另行标明",
  "recommendation": "针对用户事实和价值目标的本次建议",
  "strongest_alternative": "支持另一选项的最强理由，不只是推荐方案的风险",
  "change_if": "哪个新增证据会推翻当前推荐",
  "sources": [
    {"source_id": "填实际读过的来源ID", "start_line": 14, "end_line": 20}
  ],
  "action": {
    "owner": "用户（或实际责任人）",
    "deadline": "建议3天内，按任务调整",
    "limit": "建议最多2小时整理，暂不新增资金投入；不是用户已确认预算",
    "artifact": "一页带证据的对比表",
    "continue_if": "关键假设获得哪类可核验证据",
    "stop_if": "何种信息缺失、证据相反或投入越界时停止"
  }
}
```

示例ID是字段说明，不可原样调用；填写真实检索并读过的ID和行号。没有充分文章依据时用 `evidence_status: "insufficient"`、`sources: []`，`author_view`明确不能断言作者立场，再给标注的一般分析。不为了通过检查而凑引用。

## 处理输出

- `valid=false` 或非零退出：按 `errors` 修正原草稿再检查；不得删除失败记录或谎称已通过。来源未知/越界/目录卡被拒绝时，回到可核验正文或承认资料不足，不能换一个看似相关的ID。
- `valid=true`：只代表字段非空、引用能定位且元数据可解析。返回的 `sources` 是目录/正文解析出的真实标题、日期、URL、路径、行号与哈希；它不能证明观点确实被引用段落支持，也不能证明模型已理解全文。
- 在自然语言中使用返回的原文URL，不让长本地路径代替链接。保留“作者方向”和“本次建议”的差异、最强反方和改判证据。
- 输出末尾保留完整一行：`下一步：责任人／期限／投入上限／产物／继续条件／停止条件`。未知处直说待确认；可先给低成本取证动作。期限/上限为建议时标明，不代填用户资产或风险承受。

检查器不判断医疗/法律/金融当前事实、收益真实性、理由是否充分、反方是否够强或实际建议是否合适。这些仍需原文核验、必要的当前信息和人工/主代理审阅；不能把结构检查当成自动执行授权。
